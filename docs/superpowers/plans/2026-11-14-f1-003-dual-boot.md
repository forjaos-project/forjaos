# F1-003 — Dual boot, Secure Boot e pós-instalação

**Goal:** entregar a base segura de dual boot/MOK e o componente visual inicial de FR-013, mantendo o aceite funcional de FR-011/FR-012/FR-013 vinculado às provas que ainda faltam (issue #55).

**Architecture:** manter o Anaconda interativo e o payload remoto assinado conforme ADR-0035. O instalador apresenta as opções nativas de armazenamento, sem Kickstart de particionamento automático. Reutilizar a chave e o comando de enrollment MOK da base ublue; não criar nem distribuir chave privada própria. Um setup idempotente de primeiro boot detecta a entrada EFI do Windows e ajusta RTC somente quando aplicável. Uma regra udev no caminho de fornecedor em `/usr/lib/udev/rules.d/` passa `ro` às montagens NTFS via UDisks, sem gravar em `/etc`. A tela QML de segurança será um componente reutilizável para o wizard FR-020, que ainda não tem runtime no repositório. Não haverá launcher separado: o runtime Qt/QML CLI não está na imagem e incluir uma dependência Qt fora das licenças permitidas pelo G4 não é aceitável. O componente reporta estados desconhecidos até o host do wizard conectá-lo a detecção real. Nenhum teste grava em disco físico: instalação e redimensionamento são exercitados apenas em discos virtuais descartáveis.

**Tech Stack:** Python e unittest para configuração do instalador; Bash e testes em shell para setup de primeiro boot; systemd; Anaconda/GRUB da base Fedora Atomic; QEMU/OVMF para validação em VM.

## Tarefas

### 1. Fixar o contrato de armazenamento interativo (FR-011, ADR-0035)

**Arquivos:** `scripts/tests/test_installer_config.py`, `image/build_files/installer/configure_installer.py`.
**Teste:** exigir escolha explícita no Anaconda e rejeitar `clearpart`, `autopart`, `ignoredisk` e `zerombr` em qualquer Kickstart gerado; verificar configuração de suporte a Windows/GRUB sem selecionar disco automaticamente.
**Pronto:** testes provam que a instalação não apaga ou redimensiona discos sem escolha explícita.
**Commit:** `feat(image): preserve Windows in interactive installation`.

### 2. Especificar a tela inicial de segurança (FR-011, FR-012, FR-013, FR-020, ADR-027, ADR-028)

**Arquivos:** `docs/telas/forjaos_wizard_preflight_dual_boot/code.html`, `scripts/gen_tela_specs.py`, `docs/design-system/telas/forjaos_wizard_preflight_dual_boot.md`.
**Teste:** gerar a spec da nova tela e rodar `python3 scripts/gen_tela_specs.py --check`; revisar medidas e tokens contra o protótipo.
**Pronto:** prévia deixa dados simulados explícitos; texto pt-BR cobre Fast Startup, BitLocker, NTFS somente leitura e MOK; spec registra dimensões e conteúdo.
**Commit:** `docs(image): specify dual-boot firstboot warning`.

### 3. Exibir instruções de Secure Boot e aviso de dual boot (FR-012, FR-013, NFR-022, ADR-001)

**Arquivos:** `image/firstboot/Preflight.qml`, `image/Containerfile`, `docs/design-system/telas/forjaos_wizard_preflight_dual_boot.md`, `scripts/tests/test_firstboot_preflight.sh`.
**Teste:** verificar avisos bilingues, estados de entrada desconhecidos, sinal `continueRequested` e ausência de comandos que alterem disco ou firmware; conferir que a imagem instala o componente sem adicionar ferramentas Qt.
**Pronto:** componente QML de segurança pronto para hospedagem pelo wizard FR-020 e preview visual aprovado. A execução em VM e a comparação QML renderizada ficam pendentes até existir o runtime do wizard; FR-013 não será declarado aceito nesta entrega sem a tela visível no 1º boot.
**Commit:** `feat(image): add dual-boot preflight screen component`.

### 4. Configurar pós-instalação idempotente (FR-013)

**Arquivos:** `image/build_files/firstboot/setup-dual-boot.sh`, `image/build_files/firstboot/setup-dual-boot.service`, `image/build_files/firstboot/90-forjaos-ntfs-readonly.rules`, `image/Containerfile`, `scripts/tests/test_firstboot_dual_boot.sh`.
**Teste:** simular com diretórios temporários entrada EFI do Windows presente/ausente e execução repetida; garantir que RTC só muda quando Windows é detectado. Validar que a regra udev se aplica a NTFS com opção `ro` e não altera outros sistemas de arquivos.
**Pronto:** serviço de primeiro boot executa uma vez, não altera discos nem partições, declara `MemoryMax`, `CPUQuota` e `Nice`; teste cobre presença e ausência de Windows e a montagem NTFS somente leitura.
**Commit:** `feat(image): configure safe Windows coexistence on first boot`.

### 5. Documentar o instalador e executar ensaios descartáveis (FR-011, FR-012, FR-013)

**Arquivos:** `docs/install.md`, `docs/evidence/f1-003/`, `.github/workflows/iso.yml` se necessário para disponibilizar as provas.
**Teste:** executar instalador em VM UEFI com disco virtual que contenha Windows e disco de destino descartável; após a instalação, verificar Windows no GRUB e inicializável, status da chave/MOK, RTC e NTFS somente leitura.
**Pronto:** instruções em pt-BR. Este ambiente não tem QEMU/OVMF nem o host FR-020 para executar e capturar a tela; ensaio real de Windows/GRUB e MOK permanece pendente, assim como o DoD físico de dois hardwares do PRD.
**Commit:** `docs(image): document dual-boot installation and evidence`.

## Gates

- Cada teste novo deve ser observado em estado red antes da implementação e green após ela.
- Rodar suíte de shell, testes Python, `scripts/check-tokens.sh`, validação do roadmap e build/boot da ISO conforme `/test`.
- Não iniciar instalação, redimensionamento, gravação de mídia ou alteração de partição em hardware físico sem autorização explícita para o dispositivo e ação específicos.
- Não declarar FR-011/FR-012 aceitos sem o DoD físico de dois hardwares descrito no PRD.
- A página QML deste plano não é um wizard autônomo. A ativação em sessão gráfica depende do host FR-020; não instalar `qt6-qtdeclarative-tools`, ausente na base e incompatível com a lista de licenças G4.
