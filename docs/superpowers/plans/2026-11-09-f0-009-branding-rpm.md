# F0-009 Branding RPM and Inherited Startup Plan

**Goal:** Replace the two inherited Fedora identity RPMs with a real `forjaos-branding` RPM while preserving dependency capabilities and the KDE startup behavior needed by both bootc variants (FR-002, FR-003, FR-006).

**Architecture:** Build the RPM in a disposable build stage using the same base image as the target variant. Declare the exact `fedora-release-identity` capability required by that base, provide `system-logos`, and obsolete only the two inherited identity packages. Install the local RPM through the package manager in the final stage so the RPM database and dependency solver remain authoritative. The image configuration helper applies the variant-specific identity after the transaction. Audit unowned Bazzite startup entries before changing any of them; keep functional user units until a VM boot proves a replacement. The unchanged branding checker measures the residual visual work in issue #25 (FR-002, ADR-032).

**Tech Stack:** RPM spec, `rpmbuild` from Fedora's official repositories in a disposable stage, Containerfile, Python unit tests, shell integration checks, Docker/Podman builds, bootc lint. The runtime adds one project-owned RPM and no third-party repository. Existing approved ForjaOS logo art retains its recorded license (G4).

**Entry:** Issue #33 defines F0-009 acceptance; issue #25 is the parent failure. The roadmap claim is published on `feat/F0-009-branding-rpm`. This item does not implement a screen or change the strict checker. Screen themes and wallpapers belong to F1-006/F1-007.

## File map

- `image/Containerfile` — isolated RPM build stage, local RPM transaction, identity configuration order.
- `image/build_files/forjaos-branding.spec` — identity package metadata, exact compatibility capabilities, obsolete relationships, and owned files.
- `image/build_files/build_branding_rpm.sh` — derive base release capability and build the RPM without a hard-coded Fedora package version.
- `image/build_files/configure_image.py` — reuse `update_os_release` at RPM build time so the owned file preserves unrelated base metadata; the final helper also applies variant-specific image fields.
- `image/build_files/80-kde-desktop.preset` — preserve the desktop preset formerly owned by the replaced identity RPM.
- `scripts/tests/test_branding_rpm.py` — package contract and real RPM transaction assertions.
- `scripts/tests/test_image_containerfile.py` — build ordering and package wiring.
- `scripts/tests/test_image_startup.sh` — test scoped startup replacements without executing user setup.
- `image/build_files/configure_startup.sh` — replace only proven inherited startup entries in the image rootfs.
- `docs/roadmap/roadmap.json` — only F0-009 transitions from `doing` to `done` at ship.
