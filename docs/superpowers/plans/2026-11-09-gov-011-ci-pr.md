# GOV-011 — CI de verificação em PR

**Goal:** cada PR roda automaticamente a verificação do gate *test*, para que "CI verde" do `/ship` (ADR-033) seja real.

**Architecture:** um workflow GitHub Actions (`verify.yml`) em `pull_request`, com os mesmos comandos do `/test`, ações fixadas por SHA, permissão `contents: read`. Um teste unittest impede que o workflow deixe de rodar algum comando do gate.

**Tech Stack:** GitHub Actions, Python unittest, Pillow (só no CI, para os testes dos PNGs do logo; licença HPND).

## Mapa de arquivos
- Criar `.github/workflows/verify.yml`
- Criar `scripts/tests/test_verify_workflow.py`
- Alterar `.claude/commands/ship.md` e `AGENTS.md` (bloco Fluxo regenerado): remoção do worktree no ship

## Tarefa 1 — Workflow e teste (ADR-033, GOV-011)
- Arquivos: os dois primeiros acima.
- Prova: `python3 -m unittest scripts.tests.test_verify_workflow`; remover um comando do workflow faz o teste falhar.
- DoD: os 8 comandos da verificação rodam no PR; nenhuma ação sem SHA.
- Commit: `ci` não é escopo permitido; usar `chore(agents): add PR verification workflow`.

## Tarefa 2 — Limpeza de worktree no /ship (ADR-033)
- Arquivos: `.claude/commands/ship.md`, `AGENTS.md`.
- Prova: `scripts/check-agents-sync.sh` OK.
- DoD: passo 4 do `/ship` manda remover o worktree local.
- Commit: `docs(agents): remove worktree on ship`.

## Fora do escopo
Não marcar o check como obrigatório na `main`: PRs abertos pelo `GITHUB_TOKEN` (roadmap-sync) não disparam workflows e ficariam bloqueados.
