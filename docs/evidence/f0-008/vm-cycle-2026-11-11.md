## Automated VM CI gate

The complete Bazzite → switch → upgrade → rollback cycle has not yet run successfully on a GitHub-hosted runner. The controller and its state assertions passed locally with fake transports, but those tests are not VM evidence.

- [Run 43032461929](https://github.com/forjaos-project/forjaos/actions/runs/43032461929) on Ubuntu 24.04 reached `bcvk libvirt run` and failed before VM creation with `crun: setns mnt: Bad file descriptor`.
- [Run 43034197467](https://github.com/forjaos-project/forjaos/actions/runs/43034197467) on Ubuntu 26.04 was cancelled after two attempts; both runners failed to resolve Ubuntu package mirrors during host-tool installation.
- [Run 43037770639](https://github.com/forjaos-project/forjaos/actions/runs/43037770639) returned to Ubuntu 24.04 with a direct Podman runtime probe, but its runner also failed to resolve `azure.archive.ubuntu.com` before reaching the probe.
- [Run 43038682930](https://github.com/forjaos-project/forjaos/actions/runs/43038682930) fails early when the Ubuntu mirror cannot be resolved. Both attempts stopped before installing host tools or starting a VM.
- [Run 43040215616](https://github.com/forjaos-project/forjaos/actions/runs/43040215616) showed that the runner's `systemd-resolved` default server could not resolve the Ubuntu mirror, while a read-only query through `1.1.1.1` succeeded. A temporary per-interface DNS override was configured with an exit trap to restore the runner configuration after host-tool installation; no `/etc` file was edited.
- [Run 43040585171](https://github.com/forjaos-project/forjaos/actions/runs/43040585171) installed the tools, passed the direct Bazzite Podman probe, and resolved the signed target. `bcvk libvirt run` then failed before creating the VM with `crun: setns mnt: Bad file descriptor`.
- [Run 43041815910](https://github.com/forjaos-project/forjaos/actions/runs/43041815910) reproduced that failure on Ubuntu 26.04 with its newer Podman. Thus a host-version change alone did not fix it.
- [Run 43043231495](https://github.com/forjaos-project/forjaos/actions/runs/43043231495) additionally passed a detached Bazzite `podman run` plus `podman exec` probe, but `bcvk` still failed creating its base disk: the ephemeral container vanished and readiness timed out after 240 seconds. No status JSON was emitted.
- [Run 43045223358](https://github.com/forjaos-project/forjaos/actions/runs/43045223358) replaced `bcvk` with a pinned `bootc-image-builder` container on Ubuntu 26.04. The builder rejected a legacy `customizations.filesystem` blueprint and its inner osbuild container failed a storage mount with `permission denied`; the job never reached libvirt.
- [Run 43046165557](https://github.com/forjaos-project/forjaos/actions/runs/43046165557) built the Bazzite QCOW2 on Ubuntu 24.04, started the VM, and reached a responsive QEMU guest agent. Its first `guest-exec` of `/usr/bin/bootc status --json` failed with `Permission denied`. The image's `/usr/bin/bootc` is mode 755, so a guest-agent execution restriction is suspected but not yet confirmed. No status JSON was emitted.
- [Run 43052793621](https://github.com/forjaos-project/forjaos/actions/runs/43052793621) reproduced the `bootc` execution denial. A diagnostic handler then misread the scalar handle returned by QEMU `guest-file-open` as an object, so it failed before collecting the guest context and alternate-execution probes. The handler was corrected against QEMU's command schema; no state JSON was emitted.

Therefore the FR-008 CI acceptance gate remains open, and PR #45 must remain a draft. A successful CI artifact containing the seven `bootc status --json` states is required before review and ship.
